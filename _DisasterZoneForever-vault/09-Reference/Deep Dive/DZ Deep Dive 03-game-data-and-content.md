# 03 - Game data and content (what must be re-sourced for Forever)

Scope: `addon/DisasterZone/Data/`, `dev/generators/`, `dev/generators/data`, `dev/data`, `dev/thirdparty`, and the Core / Sim / Render3D modules that consume content. Clone: `dz-dev` (read-only, not modified). Paths below are relative to the clone root unless they start with `Core/`, `Data/`, `Sim/`, `Render3D/` (those are under `addon/DisasterZone/`).

## Summary

- `Data/` holds 27 top-level files plus `BossMods/` (9), `Classes/` (3) and `Tours/` (2): about 64K lines. About 75% of the lines sit in five generated files: `Atlas.lua` (14.6K), `SimAPL.lua` (14.6K), `AtlasClassic.lua` (12.9K), `SimItems.lua` (6.0K), `Items.lua` (2.3K).
- Almost every content file is **generated**, with a header line `AUTO-GENERATED by gen_*.py`. The generators are offline Python scripts. They read third-party addon data from a **hard-coded Windows AddOns folder** (`C:\World of Warcraft\_anniversary_\Interface\AddOns`, e.g. `dev/generators/gen_cdloot_data.py:24`, `gen_bis_lists.py:16-17`, `gen_itemclasses.py:19-20`, `gen_boss_abilities.py:26`). They also read the installed client's CASC, wago.tools DB2 tables pinned to **build 2.5.6.69795** (`gen_map_overlays.py:22`, `gen_model_index.py:32`, `gen_rooms.py:1269`), AzerothCore (WotLK) and cMaNGOS TBC world DB dumps, the WoWSims TBC repo, and Wowhead `/tbc/` pages.
- Most of those inputs are **not in the repo**. That covers the AtlasLoot / Loon / DBM / Questie installs, `dev/ext/wowsims-tbc`, `dev/art/tbcdb`, `dev/art/casc` and `dev/art/rooms` (see `.gitignore`). Only small caches are committed: `dev/generators/data/*.json` and `dev/art/blizzard_maps/*.jpg` (33 maps).
- The **engines are mostly expansion-neutral**. Atlas browser, BiS lists, ItemDB indexes, strategy boards, boss-mod runner, Render3D, raid planner, groups board, class-planner machine and sim core all work over `ns.Data.*` tables keyed by raid/boss keys. Swapping the data is the main job.
- There is a **head start**. `Data/AtlasClassic.lua` (from `gen_atlas_classic.py`, AtlasLootClassic `data.lua`) already carries every vanilla raid (MC, Onyxia, BWL, ZG, AQ20, AQ40, Naxx, world bosses) and all 25 vanilla dungeons, plus Classic crafting, reputation, PvP, events and sets (`Data/AtlasClassic.lua:17,1542,4034,5930,6163,6705,6860`). That is the vanilla base Forever builds on, but it lacks Forever's new zones, dungeons and raids.
- Mechanics to **drop or rework** for Forever:
  - **Gems, sockets and Jewelcrafting**. Forever lists no Jewelcrafting, and the skill cap is 300.
  - **Badge of Justice / Sunmote vendors, arena points and arena teams, heroic 5-mans with rep keys and dailies, attunement quests, Outland group quests and world PvP, 25-man raid sizes, TBC phases P1-P5**.
  - **TBC rotation timers**: Seal of Blood twisting, Steady Shot, Earth Shield / Heroism.
  - **The level-70 milestones**.
- Two **platform risks** for content consumers:
  1. Forever **obfuscates item data in the client**. Items only appear once a player's cache sees them, and Wowhead's guides say "80% of the items in the game are currently obfuscated". CASC- or DB2-based item generation will be incomplete for a while.
  2. Forever enables **Midnight's addon disarmament ("secrets")**. Every combat-log-driven feature (BossMod, BossLearn, swing and shot timers, gear-sim log replay, meters) needs a feasibility check on 1.60.1 before any data is rebuilt.
- **Hyjal Summit name collision**. TBC's `HyjalSummit` (25-man, Winterchill to Archimonde, instance 534) and Forever's Hyjal Summit (20-man, 13 new bosses) are different raids. Never reuse the TBC key `HyjalSummit` or planKey `hyjal`, because saved data and the sync wire depend on them (`Data/Raids.lua:7-9`).

## Generator pipeline

Environment: Windows dev kit. Scripts run with `luaenv\Scripts\python.exe generators\<script>.py` (e.g. `gen_boss_journal.py` docstring) or `bash dz.sh <wt> generators/...` (`gen_group_quests.py` docstring). The Python env is git-ignored (`dev/luaenv/`). Most scripts write only with `--write`, and print a report without it (`gen_bis_lists.py`, `gen_itemclasses.py`).

Dependency chain (loot side). Each generator imports the one before it and reuses its Lua tokenizer and table walkers:
```
gen_cdloot_data.py (raids -> Items.lua)
  -> gen_cdloot_dungeons.py (5-mans -> Dungeons.lua; validate_dungeons.py re-derives independently)
  -> gen_cdloot_sources.py (crafted / rep / badge / PvP -> Sources.lua)
     -> gen_atlas.py (everything else TBC -> Atlas.lua)
        -> gen_atlas_classic.py (same walkers over data.lua -> AtlasClassic.lua)
gen_itemclasses.py (Requirements.lua -> ItemClasses.lua; reads the generated Data files to know which ids matter)
gen_atlas_portraits.py (CASC + wago Journal -> AtlasPortraits.lua)
```
BiS / gear side:
```
gen_bis_lists.py   LoonBestInSlot Guides -> BiSLists.lua
gen_gems.py        WoWSims TBC db.json (downloaded to dev/generators/data/wowsims_tbc_db.json) + Wowhead TBC tooltips + Loon -> Gems.lua
gen_sim_items.py   dev/ext/wowsims-tbc -> SimItems.lua
gen_sim_apl.py     dev/ext/wowsims-tbc ui/specs/*/apls + dev/data/apl -> SimAPL.lua
dev/tools/gearsim/ check_export.py, wowsims_ref.py, item_sweep.py: verify the Lua sim against the real WoWSims
```
Raid strategy / 3D side (Addendum K):
```
gen_boss_portraits.py (ROSTER + Questie + wowhead/tbc npc pages) -> BossPortraits.lua
gen_boss_journal.py (CASC by name) -> BossJournal.lua
gen_boss_abilities.py (DBM-Raids-BC + spell_dispel.json) -> BossAbilities.lua
fetch_npc_spots.py (wowhead zone / npc mapper data) -> data/npc_spots.json
gen_raid_maps.py (dev/art/blizzard_maps jpg -> Media/Maps/*.blp) -> RaidMaps.lua
encounter_assets.py (data/encounter_assets/*.json) + gen_starter_strategies.py (AzerothCore spawns) -> StarterStrategies.lua, EncounterSpawns.lua
gen_model_index.py (AzerothCore templates + wago DB2 2.5.6 + local M2s) -> ModelIndex.lua
gen_rooms.py (CASC WMO / ADT geometry via casc_local.py, wago UiMapAssignment, AzerothCore creature.sql) -> DisasterZone_Rooms/Rooms/*.lua + Render3D/Rooms/Index.lua
gen_standins.py -> DisasterZone_Rooms/Standins (depth proxies)
```
World side:
- `gen_group_quests.py` reads the cMaNGOS TBC DB (`tbcdb.py`, `dev/art/tbcdb`, git-ignored) and writes `GroupQuests.lua`.
- `gen_map_overlays.py` reads wago DB2 and writes `MapOverlays.lua`.

Re-run prerequisites, none of which are in the clone:
- A Windows WoW install with AtlasLootClassic, Questie, LoonBestInSlot, DBM-Raids-BC / DBM-Outlands, LootReserve.
- The WoWSims TBC checkout in `dev/ext/`.
- The cMaNGOS `tbcdb.sql` in `dev/art/tbcdb`.
- The CASC caches in `dev/art/casc`.
- Network access to wago.tools, raw.githubusercontent (AzerothCore) and Wowhead. Wowhead returns 403 to scripts on normal pages (`gen_boss_abilities.py` docstring); the `nether.wowhead.com` tooltip API and the search-suggestion API do answer.

## Forever data sources

| Source | What | Status |
|---|---|---|
| Wowhead Forever section | Exists at `https://www.wowhead.com/forever` ("Forever News and Guides", with locale variants `/forever/de` etc.). The live **database** answers `https://www.wowhead.com/forever/search/suggestions-template?q=<text>`, which returns Forever items, NPCs, races (High Order / Windshaper Skyborne), achievements such as "Sonya Darkhallow Kills (Barrow Deeps)" (id 63581) and "The Wild King kills (Hyjal Summit)" (63580), and items in the 27xxxx-28xxxx id range. | VERIFIED (curl 2026-11-08) |
| Wowhead Forever tooltip API | `https://nether.wowhead.com/forever/tooltip/item/<id>` returns JSON. Forever-only item 286300 resolves there and is "Entity not found" on `/classic/`. It is a drop-in for `gen_gems.py:103` / `gen_itemclasses.py` style lookups. | VERIFIED |
| Wowhead Forever item pages | `/forever/item=<id>` returns 403 to curl, like other Wowhead pages to scripts. Needs a browser. | VERIFIED (403) |
| Wowhead Forever BiS guides | e.g. `https://www.wowhead.com/forever/guide/classes/warrior/fury/bis-gear` (guide 35263, patch 1.60.1, updated 2026-10-29). ## Forever deltas (ordered rebuild list)

1. **Feasibility gate first.** On a 1.60.1 client, test which of these still work under the Midnight "secrets" rules: COMBAT_LOG_EVENT_UNFILTERED reads, ENCOUNTER_START, unit auras and addon messages. Without them, BossMod, BossLearn, the swing / shot timers, meters, MyLog and the sim's log replay cannot work, and their data rebuilds (steps 9-11) are moot.
2. **New content keys and meta.** Write a Forever `Data/Raids.lua` with new keys, e.g. `Onyxia40`, `BarrowDeeps`, `HyjalForever`, not `HyjalSummit` (TBC key and planKey `hyjal` are in saved data and on the wire). Include sizes 40 / 10 / 20, instanceIDs, loading-screen art, uiMapIDs, LFG icons, and LootReserve ids if any. Rewrite `ns.PHASES` / `PHASE_INFO` (`Core/Constants.lua:136-147`) for Forever's phases, with Pre-raid = dungeons / rep / crafting and no Badges. Update `Data/GroupKinds.lua` raids and sizes (append-only wire lists: a fresh repo can start new lists).
3. **Loot DB from AtlasLoot Classic Forever.** Install it (1.60.1, GPLv2) and repoint `ADDONS` in `gen_cdloot_data.py:24` and its siblings at a Forever AddOns folder. Then adapt the walkers to whatever table files it ships (likely `data.lua` + a Forever data file, not `data-tbc.lua`) and regenerate `Items.lua`, `Dungeons.lua` (vanilla + 8 new dungeons, no heroic lists), `Sources.lua` (no Badges), `Atlas.lua`, and `ItemClasses.lua` (`Requirements.lua`). Merge or retire `AtlasClassic.lua`: the vanilla tree becomes the main tree, and the era switch (`Core/Atlas.lua:185-197`) goes. Expect gaps while items are obfuscated, and plan periodic re-runs.
4. **Item names and tooltips via Wowhead Forever.** Point tooltip caches at `nether.wowhead.com/forever/tooltip/...` instead of `/tbc/` (`gen_gems.py:103`, the `gen_itemclasses.py` cache, `gen_boss_portraits.py:130` NPC pages). Questie's TBC DB inputs (`gen_cdloot_dungeons.py`) need a Forever Questie (check whether one exists) or the Wowhead search API.
5. **BiS lists.** Replace LoonBestInSlot (`gen_bis_lists.py:17`) with AtlasLoot Classic Forever's BiS lists, or with Wowhead Forever BiS guides. Treat them as volatile; they are speculative until items are de-obfuscated. Update the BiSImport / BiSExport Wowhead URLs to `/forever/gear-planner/`, and drop or replace the WoWSims export.
